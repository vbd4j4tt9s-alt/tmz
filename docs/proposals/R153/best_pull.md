# R153: BEST PULL is this server's own, and starts again every 10 minutes

Owner: "make the best pull of the day refresh every 10 minutes and its a local server only thing to increase performance".

## What it does now
- **This server only.** The BEST PULL board counts the pulls made in this server and nothing else. No MemoryStore, no DataStore, no MessagingService, nothing saved. Another server's best pull never shows here, and this one never leaves.
- **10-minute windows on the wall clock.** The window number is `os.time() // 600` (`HubDisplayRules.PullWindowIndex`), so every server's board empties at the same :00, :10, :20 ... The record is the best pull of this server in the current window; better means what it always meant (rarity, then the rarer chance, then the heavier seed, then the earlier pull). At the mark the board is empty again, as on a fresh server, and the next pull, however small, is the new record.
- **Label.** Title `BEST PULL` (no "today"), then the winner, the seed, the rarity and the chance (still the fixed `SeedRarity153` "original" odds through `PullOddsText`), and the footer `new board in 7:42` (minutes and seconds to the next mark; the owner's example, lower case). The R153 label layout is unchanged. BIGGEST FRUIT still says `BIGGEST FRUIT TODAY` and `New fruit in 5h 12m`.
- **At the mark.** The display goes back to exactly what an empty board shows: the black mystery seed with its light off, "Nobody yet", and the black silhouette where the champion's giant avatar stood. The champion's rig is destroyed by the silhouette taking its place, so every client drops the dance track and the Animator it made (the client already did that whenever the rig changed). No chat line, no chime, no Rev pop.
- **An empty board that stays empty** is not rebuilt: a window that opens on an empty board only moves the countdown (`NextAt`, the footer words). Nothing is built, replaced or bumped.
- **Announcements.** A new best pull is still one amber chat line through `PullAnnouncer` (after the puller's reveal, Legendary or better), now always for this server and per window: the first Legendary+ pull of each window is announced again. `PullAnnounceRules.RecordScope` never says `Global` any more (a Secret, Cosmic or King best pull used to be published to the other servers), `PullAnnouncer.Send` never publishes a BestPull record whatever Scope the caller asks for, and a BestPull record message from an older server is dropped on receipt. The 🌐 pull line of a Secret+ pull is the pull announcement and is unchanged. Chat title: `🏆 Name just took BEST PULL!`.
- **Test packs** (owner `/test` packs, `TestGrant`, owner-given boots, anything an owner command just gave that player) are still never counted. `/test bestpull <seed> @name` injects a test pull that lives until the next mark; `share` is refused for it (nothing to share).
- **Old data.** A `pull` field that R151 / R152 servers wrote into the shared MemoryStore document is ignored: never read, not kept, not written back (the document now holds `{v, fruit}`), nothing is deleted or migrated. It expires with its key.

## Traffic and work removed
- No BEST PULL read, write, compare-and-set, read-back, backoff or budget use in MemoryStore (`HubDisplayStore.Merge` refuses anything but the fruit before it counts a request). The poll that reads the shared document stays, for the fruit alone, at the same cadence.
- No MessagingService publish for a best pull record and no subscribe for one (an older server's record message is dropped).
- No periodic poll for it. Server work is one integer comparison per 5 s step and one extra wake each 10 minutes (the loop sleeps `min(5, seconds to the mark)`, so the board empties within about a second of the mark). No per-frame server work.
- Client: one text write a second per BEST PULL label while it is within its 420 stud range (the write happens only when the words change), every 5 s from further away (same as the fruit's).

## BIGGEST FRUIT TODAY
Unchanged: shared across servers, daily, same store, key, poll, write gap and budget. The only shared code that moved: the stored document no longer carries a `pull` (see above), `_syncDay` / `_merge` / `_push` / `_needsWrite` work on the fruit board alone, the owner status line's first row says "new fruit in" (it said "new board in" for the day), and the client's footer goes through `HubDisplayRules.FooterCountdown`, which is `Countdown` for the fruit (same text).

## Notes
- The window uses `os.time()`, so servers whose clocks differ by a second reset a second apart; that is invisible and costs nothing.
- A pull in the last seconds of a window still gets its chat line after its reveal, which can land just after the board has emptied; the line is true when it is told.
